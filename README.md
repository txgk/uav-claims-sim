# uav-claims-sim

Имитационная модель децентрализованного распределения задач ситуационного мониторинга
территории группой беспилотных летательных аппаратов при эпизодической связи. Код
и данные к статье:

> Аль-Мерри Г., Кириллов Г. Е. Децентрализованное распределение задач ситуационного
> мониторинга территорий между автономными агентами при эпизодической связи //
> Перспективные телекоммуникационные технологии и развитие цифровых кластеров в России
> и мире (ПКМ 2026): сб. науч. ст. СПб.: СПбГУТ, 2026.

*Simulation model of decentralized task allocation for situational monitoring by a UAV group
with intermittent communication: a claim of a silent agent is trusted with the posterior
probability that the agent is still operational. Code and data for the paper above.*

## Что моделируется

Восемь аппаратов патрулируют территорию 50 × 50 км с пунктом управления (ПУ) в центре.
В течение 7 ч смены возникают ситуации трёх классов важности; о 70 % из них ПУ узнаёт
из внешних источников, об остальных — только от бортовых датчиков. Аппарат объявляет свой
маршрут заявками «ситуация — плановое время прибытия». Связь есть между аппаратами
на расстоянии не больше R и между аппаратом и ПУ на расстоянии не больше 2R; внутри
связной группы сведения передаются по цепочке, ПУ раз в минуту рассылает сводку всем.
Аппарат может «тихо» отказаться работать (вероятность 0,3 за смену): его заявки остаются
в сведениях остальных.

Правила выбора задач различаются только доверием ρ к чужим заявкам:

| Правило | ρ | В коде |
|---|---|---|
| независимые агенты | 0 | `method="indep"` |
| жёсткие заявки | 1 | `method="hard"` |
| фиксированный таймаут T0 | 1, пока молчание короче T0, затем 0 | `method="ttl"`, `ttl=` (с) |
| затухающее доверие | π(τ)·e^{−σδ}, формулы (1) и (3) статьи | `method="proposed"` |

Требование осматривать важные ситуации с вероятностью не ниже X (условие (5) статьи)
задаётся параметром `x_req=(X_A, X_B, X_C)`. Все параметры модели — в `sim/model.py`, класс
`Config`; значения по умолчанию соответствуют статье.

## Состав

```
sim/model.py        модель: территория, ситуации, отказы, связь, правила выбора задач
sim/experiments.py  серии экспериментов -> results/*.json
sim/figures.py      рисунки 1–4 статьи -> figures/
sim/article_numbers.py  все числа, приведённые в тексте статьи
sim/stats.py        средние, доверительные интервалы, парные разности
sim/style.py        оформление рисунков (шрифт, цвета, десятичная запятая)
sim/check.py        проверка воспроизводимости
results/            данные, на которых построены рисунки и числа статьи, и SHA256SUMS
figures/            рисунки в том виде, в каком они стоят в статье
```

## Установка

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Для рисунков нужен шрифт Liberation Serif (пакет `fonts-liberation` в Debian/Ubuntu,
`ttf-liberation` в Arch); без него matplotlib подставит другой шрифт.

## Запуск

```bash
make quick         # ≈ 10 с: шесть прогонов заново и сравнение с results/main.json
make experiments   # все серии заново -> results/*.json (≈ 20 мин на 2 ядрах)
make figures       # рисунки 1–4 -> figures/
make numbers       # все числа из текста статьи
make verify        # SHA-256 файлов results/*.json против results/SHA256SUMS
```

Без `make`: `cd sim && python3 experiments.py main` и т. д. Пересчитывать данные
не обязательно: `make figures` и `make numbers` работают с данными из `results/`.

## Серии экспериментов

| Серия | Что меняется | seed | Прогонов | Время на 2 ядрах |
|---|---|---|---|---|
| `main` | R = 1, 2, 3, 5, 7, 10, 15, 20 км × 5 правил (независимые, жёсткие, таймауты 15 и 30 мин, затухающее доверие) | 5000–5029 | 1200 | ≈ 9 мин |
| `ttl` | таймаут 5–120 мин при R = 2, 5 и 15 км | 5000–5029 | 810 | ≈ 6 мин |
| `validity` | записи о каждой заявке молчащего агента (затухающее доверие), R = 2, 5 и 15 км | 5000–5005 | 18 | 10 с |
| `redundancy` | затухающее доверие с X = (0,9; 0; 0) и (0,99; 0,9; 0) при всех R; то же и без требования при вероятности отказа 0,7, R = 2 и 5 км | 5000–5029 | 660 | ≈ 5 мин |

При одном seed у всех правил одинаковы ситуации, отказы и маршруты патрулирования
(общие случайные числа), поэтому правила сравниваются попарно на одних и тех же сценариях.

## Формат данных

`main.json`, `ttl.json`, `redundancy.json` — списки прогонов, по словарю на прогон:

| Поле | Смысл |
|---|---|
| `seed`, `method`, `R` (м), `ttl` (с), `fail`, `x_req` | конфигурация прогона |
| `value_share` | индекс качества мониторинга J |
| `ontime_share`, `ontime_c0..c2` | доля ситуаций, осмотренных до срока актуальности (всего и по классам; 0 — самый важный) |
| `dup_share`, `dup_c0..c2` | доля повторных осмотров среди всех осмотров |
| `value_c0..c2` | индекс J по классам важности |
| `miss_unknown`, `miss_other`, `miss_ghost` | доли ситуаций, упущенных к сроку: о них не знал ни один исправный агент / прочее / каждый знавший видел заявку-призрак с более ранним прибытием и доверием больше 0,5 |
| `miss_*_c0..c2` | то же по классам (доля от числа ситуаций класса) |
| `ghost_n` | число задач, числившихся за агентами в момент их отказа |
| `ghost_taken30`, `ghost_never` | доля таких задач, осмотренных другими не позднее 30 мин после отказа / не осмотренных до срока |
| `ghosts` | по каждой такой задаче: `lat_min` — через сколько минут после отказа её осмотрел другой агент (`null` — не осмотрел до срока), `knowers` — сколько исправных агентов знали о ней в момент отказа, `cls` — класс |

`validity.json` — прогоны с полем `validity`: массивы `tau` (длительность молчания владельца
заявки, с), `valid` (действительна ли заявка), `rho` (доверие к ней), `pos` (место задачи
в маршруте владельца), `mu` (оценка интенсивности сообщений о владельце, 1/с), `alive`
(исправен ли владелец).

Доли перехвата по нескольким прогонам считаются по всем задачам вместе (`stats.taken`).

## Воспроизводимость

Каждый прогон определяется конфигурацией и seed: случайные потоки задаются
`numpy.random.default_rng([seed, k])`, поэтому результат не зависит от числа процессов
и порядка выполнения. Пересчёт всех серий даёт файлы, совпадающие с `results/` байт
в байт (проверка — `make verify`).
